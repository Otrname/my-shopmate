# 阶段 0：环境与工具

## 1. 终端

**是什么**：用打字命令操作电脑的窗口。

**常用命令**

| 命令 | 作用 |
|---|---|
| `pwd` | 显示我现在在哪个文件夹 |
| `ls` / `ls -a` | 列出当前文件夹里的文件 / 包括隐藏文件 |
| `cd 文件夹` | 进入文件夹；`cd ~` 回到主目录 |
| `mkdir 名字` | 新建文件夹 |
| `cat 文件` | 显示文件内容 |

**踩过的坑**
- 在主目录运行 `open -e .env`，提示文件不存在。原因：当时不在项目文件夹里。解决：先 `cd ~/Desktop/项目名`。
- `git commit -m “说明“` 报 `pathspec 'PyCharm' did not match`。原因：用了**中文引号 “ ”**，终端不认，把说明拆成了好几个文件名。解决：命令里的引号、括号、逗号一律用**英文半角**，敲命令前切到英文输入法。
- 终端出现 `dquote>` 提示符，敲什么都没反应。原因：引号只开了没关（前面是中文 “，后面是英文 "），终端在等你把引号补全。解决：按 `Ctrl + C` 取消，重新输入。

**我的理解**：
直接使用命令来给文件做的操作,在操作文件前先cd进入这个文件目录下

## 2. Git

**是什么**：版本控制工具，给代码"存档"。

**解决什么问题**：没有它时只能靠"最终版_真的最终版"这种文件名管理版本，找不回旧版本，也不知道改了哪里。

**比喻：寄快递**

| 区域 | 比喻 | 进入方式 |
|---|---|---|
| 工作区 | 桌子 | 直接编辑文件 |
| 暂存区 | 快递箱 | `git add` |
| 本地仓库 | 封箱贴单（存档） | `git commit -m "说明"` |
| 远程仓库 GitHub | 寄出去 | `git push` |

**常用命令**

| 命令 | 作用 |
|---|---|
| `git init` | 让 git 开始管理这个文件夹（生成隐藏的 `.git`） |
| `git status` | 看桌上和箱子里有什么，**不确定时先运行它** |
| `git add 文件` / `git add .` | 放进暂存区 / 放入所有改动 |
| `git commit -m "做了什么"` | 存档 |
| `git log --oneline` | 看存档历史 |
| `git diff` | 看和上次存档相比改了哪里 |
| `git restore 文件` | 撤销改动，回到上次存档 |
| `git push` | 推送到 GitHub |
| `git rm -r --cached 文件夹` | 让 git 不再跟踪它，但保留本地文件 |

**`.gitignore`**：写在里面的文件，git 会当作不存在。必须忽略的：
- `.env`：里面有 API Key，Key 就是钱；推上去几分钟就可能被机器人盗用；删了历史里还在，只能去后台作废换新
- `.venv`：工具箱，体积大，别人用 `uv sync` 自己装
- `.idea`：PyCharm 的个人编辑器设置

**好习惯**
- 提交前先 `git status`，确认只提交了想提交的文件
- 提交说明写"做了什么"，如"新增订单查询"，不要只写文件名

**踩过的坑**
- `.idea` 被提交上去了。解决：`.gitignore` 加 `.idea/` → `git rm -r --cached .idea` → add、commit、push。

**我的理解**：
存档和找回历史版本,改东依次经过工作区、暂存区、本地仓库、远程仓库,每一步用一个命令推进

## 3. uv

**是什么**：Python 的项目和依赖管理工具。

**三个概念**
- **第三方库**：别人写好的代码，像手机 App，需要什么功能装什么（如 `anthropic`、`fastapi`、`rich`）
- **虚拟环境 `.venv`**：每个项目自己的工具箱，不同项目需要同一个库的不同版本时互不干扰
- **依赖清单**：
  - `pyproject.toml`：我的**要求**，如 `rich>=14.0`；还记录项目名、版本、需要的 Python 版本
  - `uv.lock`：实际装上的**确切版本**，保证所有人装出来一模一样

**直接依赖和间接依赖**：`uv add rich` 装了 4 个包，因为 rich 自己也依赖别的库。用 `uv tree` 查看依赖树：
```
my-shopmate
└── rich                 ← 直接依赖：我要的，写进 pyproject.toml
    ├── markdown-it-py   ← 间接依赖：rich 要的（解析 Markdown）
    │   └── mdurl        ← 间接依赖的依赖（解析网址）
    └── pygments         ← 间接依赖：rich 要的（代码高亮上色）
```
`pyproject.toml` 只记直接依赖，`uv.lock` 记全部 4 个的确切版本。

**`uv init` 生成的文件**：`main.py`、`pyproject.toml`、`README.md`、`.python-version`、`.gitignore`、`.git`
**第一次 `uv run` 才生成**：`uv.lock`、`.venv`

**常用命令**

| 命令 | 作用 |
|---|---|
| `uv init 项目名` | 新建项目 |
| `uv add 库名` | 安装库并写进清单 |
| `uv run xxx.py` | 用项目自己的工具箱运行 |
| `uv sync` | 按清单把工具箱装齐（拿到别人的项目先运行它） |

**踩过的坑**
- 直接 `python3 main.py` 报 `No module named 'rich'`。原因：rich 只装在项目的 `.venv` 里。解决：用 `uv run main.py`。

**我的理解**：
uv是包管理器,记录各项依赖的版本要求,给每个项目一个独立的工具箱,项目之间互不干扰
